# 월영록 스프라이트·런타임 모델링 규격 v2

이 문서는 이후 모든 캐릭터·몬스터 제작에 적용하는 고정 규격이다. 목표는 조선 후기 복식과 무기를 바탕으로 한 묵직한 다크 판타지 2D 사냥 화면이며, 아기자기하거나 과장된 SD 비율은 사용하지 않는다.

## 1. 미술 방향

- 장르: 조선 다크 판타지, 고전 아이소메트릭 액션 RPG 감성
- 비율: 머리 1 : 전신 6~7 정도의 현실적인 성인 비율
- 재질: 빛바랜 무명, 가죽, 무쇠, 젖은 털처럼 재질 차이가 읽혀야 한다.
- 색: 먹색·남색·갈색이 주조색이며 얼굴, 무기 날, 눈빛에만 밝은 강조색을 쓴다.
- 실루엣: 100px 안팎으로 축소해도 직업과 무기가 즉시 구분되어야 한다.
- 금지: 현대 장비, 서양 판타지 갑옷의 무분별한 혼합, 과도한 광택, SD 캐릭터, 프레임마다 복식이나 무기 형태가 바뀌는 현상

## 2. 방향 규격

원본은 아래 순서의 5행으로 제작하고 동쪽 계열 3방향은 런타임 좌우 반전으로 만든다.

| 행 | 원본 방향 | 런타임 반전 방향 |
|---:|---|---|
| 0 | 남 | 없음 |
| 1 | 남서 | 남동 |
| 2 | 서 | 동 |
| 3 | 북서 | 북동 |
| 4 | 북 | 없음 |

얼굴, 가슴, 골반, 발끝과 무기의 진행 방향이 모두 같은 방향을 향해야 한다. 공격 이펙트와 타격 판정도 캐릭터가 바라보는 각도를 사용한다.

## 3. 프레임 규격

### 몬스터 기본 시트

- 한 프레임: `256 × 256px`
- 전체 시트: `2048 × 1280px` (`8열 × 5행`)
- 0~3열: 걷기 4프레임 — 접지, 하강, 교차, 상승
- 4~7열: 공격 4프레임 — 예비, 휘두름/돌진, 타격, 회수
- 재생 속도: 걷기 9~11fps, 공격 9~11fps

### 주인공 액션 시트

- 한 프레임: `256 × 256px`
- 전체 시트: `2048 × 1280px` (`8열 × 5행`)
- 0~3열: 걷기 4프레임 — 왼발 접지, 통과, 오른발 접지, 통과
- 4~7열: 공격 4프레임 — 예비, 가속, 타격, 회수
- 재생 속도: 걷기 11fps, 공격 10~11fps
- 모든 장비 조합이 이 규격을 그대로 사용한다. 이전 `6열 × 5행` 시트와 혼용하지 않는다.
- 무기 공격의 타격 판정은 시작 후 약 `0.24초`, 주먹은 약 `0.18초`에 발생시킨다.

## 4. 크기와 기준점

- 모든 프레임의 발바닥 기준선: 셀 하단에서 `7px` 위
- 최대 캐릭터 영역: 가로·세로 `232px` 이내
- 최소 안전 여백: 상하좌우 `12px`; 긴 무기만 필요한 범위에서 예외 허용
- 런타임 원점: `origin(0.5, 0.97)`을 기본값으로 사용
- 현재 권장 표시 배율: 주인공 `0.51`, 도깨비 `0.50`, 멧돼지 `0.52`, 인간형 몬스터 `0.51`
- 같은 종의 프레임 간 키·몸통 폭 변화는 8% 이내로 제한한다.

캐릭터의 발, 무기, 그림자가 이웃 셀에 걸치면 안 된다. 원본 격자를 고정 폭으로 바로 자르지 말고 알파 연결 영역을 기준으로 각 포즈를 분리한 뒤 동일한 발 기준선에 재배치한다.

### 런타임 좌표 분리

- 월드 이동 좌표는 `Container` 루트가 담당한다.
- 스프라이트는 컨테이너 내부 `(0, 0)`에 두고, 공격 돌진·피격 흔들림·사망 낙차만 자식 스프라이트의 로컬 좌표로 표현한다.
- 매 프레임 월드 좌표를 스프라이트에 직접 덮어쓰지 않는다. 그렇게 하면 공격 돌진과 사망 트윈이 끊긴다.
- 걷기에는 임의의 사인파 회전·스쿼시·상하 바운스를 더하지 않는다. 제작된 보행 프레임과 접지 그림자만 사용한다.
- 접지 그림자는 발 기준선 아래에 두고, 이동 중에도 머리나 몸 위로 이동하지 않게 루트 컨테이너에 포함한다.

### 주인공 장착 외형 조합

주인공은 게임 시작 시 무기·복장·부적 슬롯이 모두 비어 있다. 기본 외형은 갓, 도포, 허리 장비, 신발, 무기가 없는 맨상체·최소 속바지·맨발이다. 미착용 원본에 도복 상의나 외투 실루엣을 그리지 않는다.

| 무기 | 복장 | 사용 외형 | 기본 공격 |
|---|---|---|---|
| 없음 | 없음 | 맨상체·속바지·맨발 | 주먹 |
| 장착 | 없음 | 맨상체·속바지·맨발+장착 무기 | 무기 공격 |
| 없음 | 장착 | 장착 복장+빈손 | 주먹 |
| 장착 | 장착 | 장착 복장+장착 무기 | 무기 공격 |

새 장비 외형을 만들 때도 위 네 조합이 깨지지 않는지 확인한다. 무기만 장착했는데 갓이나 도포가 생기거나, 복장만 장착했는데 무기가 생기면 안 된다.

- 빈손 보행과 맨손 공격은 `joseon-hero-base-body-v8`을 사용한다.
- 무기를 장착한 대기·보행·공격은 장비가 합쳐진 완성 캐릭터가 아니라 `joseon-hero-weapon-ready-body-v3`을 사용한다. 이 몸의 0~3열은 `joseon-hero-base-body-v8`의 승인된 전 방향 맨몸 보행을 그대로 상속해 발 교차와 접지감을 보존하고, 4~7열은 양손 검술 공격이며 칼 자체는 그리지 않는다.
- 공격 이벤트의 `style`이 `fist`면 맨손 원본, `weapon`이면 무기 준비 원본을 선택한다. 장착 무기와 복장은 선택된 몸 자세 위에 독립 부품으로 합성한다.
- 미착용 원본에는 상의 픽셀이 없어야 하며, 최소 속바지는 장비 복장과 혼동되지 않는 무채색으로 제한한다.
- 복장은 몸이 없는 투명 40프레임 레이어로 제작하고 몸과 동일한 frame, flipX, origin, scale을 사용한다.
- 무기 준비 자세용 복장은 `*-weapon-ready-layer-*`로 별도 정규화하되, 0~3열은 기존 복장 보행 레이어를 그대로 상속하고 4~7열은 양손 검술 소매를 포함한다. 몸·무기 픽셀은 포함하지 않는다.
- 무기는 완성 캐릭터 시트에 합치지 않는다. 투명 아이템 이미지와 방향·액션 프레임별 손 부착점으로 표시한다.
- 인게임 무기는 인벤토리 아이콘을 재사용하지 않고 `public/assets/weapons/*-world-v1.png`의 공통 손 원점 `(0.5, 0.18)` 자산을 사용한다.
- 복장 배율과 발 기준선은 복장 외곽이 아니라 `joseon-hero-base-body-v8`에서 한 번 계산하며, 모든 복장 레이어에 같은 변환을 적용한다.
- 장비별 완성 캐릭터 시트로 주인공 몸을 교체하지 않는다. 별도 완성 시트는 NPC나 참조 자산에만 쓴다.
- 복장 레이어에는 얼굴·손·발·그림자 픽셀이 없어야 하며, 몸과 합성했을 때 발이 중복되거나 보폭이 바뀌면 불합격이다.
- 현재 머리 장비 슬롯은 없으므로 네 조합 모두 갓을 착용하지 않는다.
- 빈손 외형은 40개 프레임 전체에 무기나 칼집이 없어야 한다.
- 무기 장착 외형은 40개 프레임 전체에서 같은 환도를 유지해야 한다.
- 무기 장착 보행에서는 승인된 기본 보행의 왼발·오른발 접지 차이가 유지되어야 하며, 오른손 주먹 중심과 무기 원점이 4프레임 내내 붙어 있어야 한다. 칼날은 몸통을 수평으로 관통하지 않고 몸 바깥 아래·뒤로 향해야 한다.
- 무기 준비 몸 0~3열과 공격 4~7열은 같은 발 기준선과 원점을 사용하고, 공격 종료 직후 장착 대기 0열로 돌아간다.
- 장비 상태가 바뀌면 진행 중인 이전 공격을 즉시 취소하고 새 외형의 대기 프레임으로 전환한다.

## 5. 생성·정규화 순서

1. 단색 마젠타 배경에 5방향 전신 포즈를 생성한다.
2. 복식, 얼굴, 무기, 광원 방향이 모든 프레임에서 같은지 확인한다.
3. 크로마키를 제거하고 부드러운 알파 가장자리와 색 번짐 제거를 적용한다.
4. `scripts/normalize_grid_atlas.py`로 실제 포즈 연결 영역을 추출해 256px 셀과 동일한 발선에 맞춘다.
5. 몬스터는 `scripts/expand_monster_atlas.py`로 걷기 4열+공격 4열 규격을 확정한다.
6. 완성 시트를 육안으로 확인해 잘린 무기, 떠다니는 발, 중복 신체, 빈 프레임을 제거한다.
7. Phaser에서 방향별 애니메이션을 만들고 AI의 이동·공격 상태에 연결한다.

## 6. 액션 품질 기준

- 걷기: 몸통이 미끄러지지 않고 양발 접지와 무게 이동이 읽혀야 한다.
- 걷기: 실제 게임 크기 약 90px에서도 왼발·오른발 실루엣과 상하 체중 이동이 구분되어야 한다.
- 공격: 예비 동작과 회수 동작을 포함하며 무기가 목표 방향으로 지나가야 한다.
- 타격감: 실제 타격 프레임에만 피해, 짧은 히트스톱, 피격 발광, 넉백, 충돌음을 발생시킨다.
- 몬스터 개성: 멧돼지는 예고 후 돌진, 도깨비는 근접 압박, 인간형은 간격 유지와 측면 이동을 기본으로 한다.
- 몬스터 공격: 공격 이벤트는 선딜 시작에 발생시키고 실제 피해는 약 `0.22초` 뒤 타격 프레임에서 적용한다. 공격 상태는 최소 `0.46초` 유지해 이동과 겹치지 않게 한다.
- 카메라: 월드 중앙 고정이 아니라 주인공 루트를 부드럽게 추적하며, 화면 비율이 달라져도 월드 경계 안에서 사냥 대상이 보이게 한다.

## 7. 그래픽 자원·성능 규격

- 실제 게임에 노출되는 소형 아이템 아이콘은 `256 × 256px` 배포본을 사용한다. 생성 원본은 `assets/`에 보관하고 `public/`에 중복 배포하지 않는다.
- 환경 오브젝트 배포본은 투명 PNG `768 × 768px` 이내를 기본으로 하고, 발·바닥 접점이 명확한 단일 객체로 제작한다.
- 현재 장면에서 참조하지 않는 구형 시트와 생성 원본은 `assets/legacy/`로 이동해 Vite 정적 배포에서 제외한다.
- Retina 렌더 해상도는 기기 DPR을 그대로 쓰지 않고 최대 `1.5`로 제한한다.
- DOM HUD는 매 렌더 프레임이 아니라 약 `80ms` 간격 또는 게임 이벤트 발생 시 갱신한다.
- 새 파티클은 소수의 재사용 가능한 효과로 제한한다. 영구 파티클 수를 늘려 분위기를 만드는 방식은 사용하지 않는다.

## 8. 완료 검사

- 걷기 중 발이나 다른 프레임 조각이 머리 위에 나타나지 않는가?
- 공격 방향과 실제 대상 방향이 일치하는가?
- 몬스터가 정지 이미지로 미끄러지지 않고 걷기 프레임을 재생하는가?
- 모든 종이 공격 액션을 끝까지 재생하는가?
- `npm test -- --run`과 `npm run build`가 통과하는가?
- 실제 브라우저에서 이동, 추적, 공격, 돌진, 사망·재생성을 확인했는가?
- 시작 화면에서 무기·복장·부적 슬롯이 모두 비어 있고 주먹 공격이 표시되는가?
- 장비 장착 조합에 맞는 외형과 공격 액션으로 즉시 전환되는가?
- 몸과 복장 레이어가 동일한 `5행 × 8열` 프레임 번호를 사용하고 무기가 해당 프레임의 손 부착점을 따르는가?
- 머리 장비를 장착하지 않았는데 갓이 생기거나, 빈손인데 칼이 나타나지 않는가?
- 월드 이동 중에도 공격·피격·사망 로컬 액션이 끊기지 않는가?
- 인벤토리를 열면 전투 시뮬레이션은 멈추고 장비 UI는 즉시 갱신되는가?
- 브라우저 최신 재로드 뒤 콘솔 오류가 없는가?
