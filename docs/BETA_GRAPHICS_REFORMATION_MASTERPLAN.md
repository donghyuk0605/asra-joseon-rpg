# 아스라 베타 그래픽·이미지셋 대혁명 전체 마스터 목표

이 문서는 단기 패치 목록이 아니다. 아스라의 월드, 캐릭터, 몬스터, 아이템, 전투 효과, 인터페이스가
하나의 조선 다크 판타지 게임처럼 보이고 움직이는 상태를 최종 완료 기준으로 고정한다. 일부 지역의
배경만 좋아지거나 생성 이미지만 추가된 상태, 정지 이미지를 흔들어 애니메이션처럼 보이게 만든 상태,
화면과 충돌·상호작용이 어긋난 상태는 완료로 인정하지 않는다.

## 1. 현재 기준선과 핵심 문제

2026-08-09 최신 자동 장부 기준 배포 자산은 총 472개다. 숫자가 바뀔 때는 이 문장을 손으로 추정하지
않고 `docs/graphics/VISUAL_COVERAGE_REPORT.md`의 생성 결과를 기준으로 갱신한다.

Phaser 코드에는 사각형·원·타원·폴리곤·Graphics 생성이 약 155곳 있다. 이 중 그림자, 충돌 예고,
물결, 먼지, 비, 안개처럼 실시간 변화가 필요한 표현은 코드 그래픽으로 유지한다. 성문, 깃발, 장대,
좌판, 갈대, 수레, 장승, 제단, 화로, 표지물처럼 고정된 실물 객체는 이미지셋으로 교체한다.

콘텐츠 기준선은 81개 지역, 60종 아이템, 61종 몬스터다. 그래픽 완료는 이 전체 목록에 미분류가
하나도 없을 때만 선언한다.

## 2. 고정 미술 방향

### 세계의 인상

- 장르: 임진왜란 전후 조선과 동아시아를 바탕으로 한 현실적 다크 판타지.
- 화면: 고전 아이소메트릭 액션 RPG처럼 바닥, 발, 실루엣, 이동 통로가 먼저 읽혀야 한다.
- 감정: 비에 젖은 흙, 오래 탄 목재, 빛바랜 무명, 녹슨 무쇠, 피로한 사람들의 생활감.
- 금지: 장난감 같은 비율, 과도하게 깨끗한 판타지 마을, 네온색 마법, 서양 중세 갑옷 혼합,
  지역마다 다른 게임처럼 보이는 화풍, AI 포스터 같은 과밀 구성.

### 색과 재질

- 공통 주조색: 먹색, 남색, 황토, 젖은 갈색, 탁한 녹색.
- 강조색: 얼굴 피부, 칼날, 횃불, 피, 주술 눈빛에만 제한적으로 사용한다.
- 조선: 무명·삼베·기와·소나무·철제 농기구·옹기 재질을 중심으로 한다.
- 여진: 모피·가죽·자작나무·뿔·철찰 재질을 중심으로 한다.
- 일본: 짙은 목재·회벽·대나무·라커·철포 화약 그을음을 중심으로 한다.
- 요물: 현실 재질 위에 변질의 흔적을 더한다. 물체 전체를 발광시키지 않는다.

### 형태와 카메라

- 성인 인간은 머리 1 : 전신 6~7 비율을 유지한다.
- 실제 게임 크기 90~110px에서도 계급, 무기, 세력, 성별, 행동이 읽혀야 한다.
- 모든 객체는 아이소메트릭 카메라와 동일한 시점·광원·바닥 접점을 사용한다.
- 이미지 바닥 그림자는 최소화하고, 동적 접지 그림자는 런타임에서 통일한다.
- 객체 상단 장식보다 발판, 출입구, 이동 통로가 먼저 보이게 한다.

## 3. 자산 제작과 저장 규칙

- 생성 원본은 `assets/` 아래에 보관하고 게임 배포본은 `public/assets/`에만 둔다.
- 활성 배포본은 한 자산당 한 포맷을 원칙으로 한다. 알파가 중요한 소형 객체는 PNG, 대형 배경은
  WebP를 사용한다.
- 구형 `v1`, `v2`, 중간 생성본, 사용하지 않는 PNG/WebP 쌍은 `assets/legacy/`로 이동하고
  `public/`에서는 제거한다.
- 환경 단일 객체는 투명 PNG 768×768px 이하, 아이템 아이콘은 256×256px로 배포한다.
- 파일명은 `문화권-지역-객체-상태-vN` 또는 `세력-직업-행동-vN` 구조를 사용한다.
- 모든 투명 자산은 모서리 알파 0, 녹색·마젠타 번짐 없음, 잘린 실루엣 없음, 유효 픽셀 경계와
  런타임 앵커 기록을 통과해야 한다.
- 생성 이미지는 게임에 바로 넣지 않는다. 크로마키 제거, 디스필, 크기 정규화, 바닥선 정렬,
  미리보기, 인게임 축소 검사를 거친다.
- 스프라이트는 프레임별로 따로 생성하지 않고 승인된 기준 프레임을 바탕으로 전체 스트립을 한 번에
  제작해 복식·무기·비율 표류를 줄인다.

## 4. 81개 지역의 월드 그래픽 목표

모든 지역을 서로 다른 대형 배경으로 만드는 것이 목표가 아니다. 권역별 기반 이미지셋을 공유하되
랜드마크, 생활 객체, 날씨, 전투 흔적으로 지역의 기억점을 만든다.

### 권역 기반 세트

- 울릉: 해풍 초지, 은빛 억새, 화산암, 해안 절벽, 습한 소나무, 관아와 감옥.
- 조선 도로: 흙길, 논둑, 나루, 역참, 장승, 돌무더기, 피난 흔적.
- 조선 도시: 성문, 육조거리, 저잣거리, 관아, 서원, 수군진, 산성의 크기와 격을 분리한다.
- 평양·전선: 토성, 대동강, 공성 흔적, 군영, 불탄 민가, 방어진지를 단계별로 표시한다.
- 여진 변경: 자작나무, 설원, 가죽 천막, 목책, 말먹이, 사냥 흔적, 부족별 문양.
- 일본: 세쓰 촌락, 오사카 항구, 성하마을, 성곽의 목재·회벽·대나무 언어를 분리한다.
- 던전: 광산, 침수 감옥, 봉인 사당, 지하 성소가 벽·바닥·문·함정만 보고도 구분돼야 한다.

### 모든 지역의 필수 레이어

- 바닥 기반, 이동 가능 통로, 경계 페더링, 전경 가림, 대형 랜드마크, 생활 소품, 출구 표식,
  위험 구역, 날씨·분위기 레이어를 분리한다.
- 권역 사이 연결부는 양쪽 지역의 재질과 색이 절반씩 이어져 순간적인 배경 단절이 없어야 한다.
- 출구 이미지는 실제 이동 방향과 일치하고 잠금·개방 상태가 화면에서 구분돼야 한다.
- 전경 건물과 나무는 플레이어 발 위치에 따라 앞뒤 깊이가 바뀌고, 캐릭터를 완전히 가릴 때는
  반투명 처리한다.
- 지역별 최소 한 개의 고유 랜드마크와 세 개 이상의 생활 흔적을 둔다.

### 지역 완료 판정

- PC와 모바일에서 플레이어, 출구, 위험 목표가 배경에 묻히지 않는다.
- 지역 경계와 배경 경계가 같은 위치에서 전환된다.
- 출입구·다리·골목의 보이는 폭과 실제 이동 가능한 폭의 오차가 12px 이하다.
- 같은 권역 배경을 공유해도 랜드마크만 보고 지역을 구분할 수 있다.

## 5. 환경·건축·생활 객체 전체 목표

### 이미지셋으로 반드시 교체할 객체

- 성문 문짝, 문기둥, 빗장, 목책, 감옥문, 장대, 군기, 천 깃발.
- 좌판, 천막, 수레, 물지게, 우물, 장독대, 짚단, 나무상자, 포대, 어망, 닻.
- 논밭 작물 단계, 농기구, 물레방아, 방아, 벌목 더미, 광차, 갱도 지지대.
- 장승, 서낭당, 제단, 위패, 봉인석, 화로, 횃불 받침, 종, 북.
- 갈대 군락, 억새, 대나무, 소나무·자작나무·동백나무 변형, 바위와 절벽 파편.
- 파괴 전/후 수레, 닫힘/열림 성문, 꺼짐/점화 화로처럼 상태가 있는 객체.

### 코드 그래픽으로 유지할 표현

- 접지 그림자, 선택 링, 공격 범위, 충돌 경고, 물결, 비, 눈, 안개, 먼지, 불티, 잎,
  연기와 같이 위치·크기·수명이 실시간으로 변하는 효과.
- 코드 그래픽도 색, 알파, 밀도, 성능 상한을 중앙 프리셋으로 통일한다.

### 객체 데이터 규격

모든 주요 객체는 `assetKey`, `position`, `origin`, `displaySize`, `footprint`, `occlusion`,
`interactionPoint`, `state`, `depthOffset`을 한 데이터 구조에서 관리한다. 이미지 배치와 별도로
충돌 사각형을 손으로 중복 입력하지 않는다.

### 객체 완료 판정

- 이미지 발판과 충돌 다각형이 시각적으로 일치한다.
- 클릭 가능한 객체는 화면에 동일한 상호작용 표식이 표시된다.
- 열린 문은 통과되고 닫힌 문은 막히며, 상태 전환 중 판정이 먼저 사라지지 않는다.
- 객체가 캐릭터 위에 떠 있거나 바닥 아래 박히지 않는다.
- 같은 소품을 반복 배치해도 좌우 반전·색 변형·소형 변형으로 복제 느낌을 줄인다.

## 6. 주인공과 장비 외형 전체 목표

### 네 주인공

- 김동혁, 하진, 연화, 왕세자 광해는 서로 다른 얼굴·체형·대기 자세·이동 리듬·무기 운용을 가진다.
- 각 주인공은 남·남서·서·북서·북 5방향 원본과 좌우 반전 3방향을 지원한다.
- 256×256px 프레임, 8열×5행 시트, 발선 하단 7px, `origin(0.5, 0.97)`을 고정한다.
- 0~3열은 실제 보행, 4~7열은 예비·가속·타격·회수 공격으로 사용한다.
- 걷기, 공격, 피격, 사망은 시뮬레이션 상태와 연결하고 정지 이미지 흔들기로 대체하지 않는다.

### 장착 조합

- 빈손·미착용, 무기만 장착, 복장만 장착, 무기와 복장 장착의 네 조합을 모두 검증한다.
- 몸, 복장, 무기는 독립 레이어로 합성한다. 완성 캐릭터 시트로 슬롯 상태를 속이지 않는다.
- 무기 장착 시 모든 프레임에서 손과 손잡이가 붙고 칼날·활·창이 몸통을 관통하지 않는다.
- 환도뿐 아니라 활, 장창, 방망이, 부적·방울 계열의 월드 무기 이미지와 손 부착점을 만든다.
- 장비를 바꾸면 이전 공격을 취소하고 새 외형의 대기 상태로 즉시 전환한다.

### 주인공 완료 판정

- 네 주인공 모두 새 게임과 이어하기에서 선택한 인물의 이름·초상·월드 외형이 일치한다.
- 전 방향 걷기에서 발 교차가 읽히고 미끄러짐·머리 위 프레임 조각이 없다.
- 모든 장비 조합과 공격 방향을 PC·모바일에서 확인한다.

## 7. NPC 전체 목표

- NPC를 농민, 상인, 대장장이, 주모, 포졸, 관원, 승려, 무당, 병사, 피난민, 여진 주민,
  일본 주민의 기본 계열로 나눈다.
- 기본 계열 안에서도 성별, 나이, 체형, 머리 모양, 옷 색, 소지품을 조합해 복제 인상을 줄인다.
- 직업 객체를 실루엣에 포함한다. 대장장이는 망치, 상인은 짐, 농민은 농기구, 포졸은 무기와
  관복만 보고 구분돼야 한다.
- 고유 스토리 NPC는 전용 월드 외형과 대화 초상을 가진다.
- NPC는 대기, 걷기, 작업, 대화 반응 중 실제 상태에 맞는 액션을 사용한다.
- 대화·상점·주막·대장간 상호작용 지점은 NPC 발 위치와 일치한다.

## 8. 61종 몬스터와 보스 전체 목표

### 외형 대응표

61종 모두를 다음 네 등급 중 하나로 명시한다.

- 전용 시트 필수: 보스, 주인공급 적, 동물·요물처럼 체형이 다른 종.
- 세력 계열 공유: 동일 병과이되 세력별 갑옷·문양·무기 레이어를 교체.
- 직급 변형 허용: 일반병·정예·대장은 투구, 어깨, 깃발, 무기 크기로 구분.
- 색상 변형 허용: 같은 생물의 지역 변종에만 제한하고 실루엣이 다른 종에는 사용하지 않는다.

현재처럼 울릉 포졸 시트가 영월·전주·국경군·왕실 호위까지 그대로 보이는 광범위한 공유를 없앤다.
조선, 여진, 일본, 왜구의 병사 계열은 같은 병과라도 복식과 무기, 자세가 달라야 한다.

### 몬스터 액션

- 모든 종은 4프레임 걷기와 4프레임 공격을 가진다.
- 궁수는 장전·조준·발사·회수, 조총수는 화약 점화·반동·연기, 창병은 찌르기 거리,
  기병은 말의 보행과 돌진이 실제 판정과 일치해야 한다.
- 동물은 종별 보행 구조를 공유하지 않는다. 사슴, 멧돼지, 늑대, 곰, 토끼, 표범의 척추와
  다리 리듬을 분리한다.
- 피격은 짧은 발광만이 아니라 자세 붕괴·넉백 방향이 읽혀야 한다.
- 사망은 마지막 공격 프레임 고정이 아니라 종별 쓰러짐, 잔류 시체, 소멸 순서를 가진다.

### 보스

- 모든 보스는 전용 실루엣, 전용 체력 프레임, 공격 예고 모양, 타격 효과, 사망 연출을 가진다.
- 패턴 예고 이미지와 실제 피해 영역의 오차를 8px 이내로 맞춘다.
- 보스 크기를 단순 확대해 일반 몬스터처럼 보이게 하지 않는다.

### 몬스터 완료 판정

- 61종 대응표의 미분류가 0개다.
- 모든 종의 40프레임 알파 점유, 발선, 방향, 걷기·공격 재생 테스트가 통과한다.
- 실제 전투에서 이동 중 공격 프레임이 끊기지 않고 피해 순간과 타격 프레임이 일치한다.

## 9. 60종 아이템·행낭·바닥 드롭 전체 목표

### 하나의 아이템 정체성

모든 아이템은 카탈로그의 하나의 `visualFamily`에서 다음 표현을 파생한다.

- 행낭 256×256 아이콘.
- 상세 화면 확대 이미지.
- 바닥 드롭 실루엣 또는 소형 월드 이미지.
- 장착 가능한 장비의 월드 무기·복장 레이어.
- 희귀도 테두리와 획득 광주는 별도 공통 효과로 적용한다.

아이콘과 바닥 드롭이 전혀 다른 물건처럼 보이거나, 희귀도마다 같은 아이콘에 색만 입히는 방식을
없앤다.

### 아이템 분류별 규칙

- 무기: 전체 형태, 손잡이, 칼집·활시위·창날이 읽히고 월드 부착점이 기록돼야 한다.
- 복장: 몸 없이 투명한 레이어로 만들고 모든 방향·행동 프레임과 일치해야 한다.
- 부적·장신구: 종이, 뼈, 엄니, 금속, 실 재질이 구분돼야 한다.
- 재료: 몬스터·지역의 출처가 실루엣과 재질로 연결돼야 한다.
- 소모품: 회복, 강화, 사건용 문서가 형태만 보고 구분돼야 한다.

### 행낭 화면

- 아이콘, 이름, 종류, 등급, 장착 상태, 수량, 비교 변화량, 획득처를 한 시선 흐름으로 배치한다.
- 선택·장착·판매·강화 가능 상태를 색만이 아니라 테두리, 표식, 문구로 함께 표시한다.
- 모바일에서 아이콘을 누르면 상세가 안정적으로 열리고 스크롤 위치가 보존된다.

### 아이템 완료 판정

- 60종 모두 활성 아이콘 경로가 존재하고 투명 모서리·크기·중심 검사를 통과한다.
- 모든 장착 장비는 실제 월드 외형이 있으며 슬롯 상태와 일치한다.
- 바닥 드롭, 획득 알림, 행낭, 상세 화면의 이름과 이미지가 동일 아이템을 가리킨다.
- 구형 아이콘과 사용하지 않는 SVG·PNG 중복은 배포에서 제거한다.

## 10. 전투·속성·상태이상 이미지셋 전체 목표

### 물리 전투

- 베기, 찌르기, 둔격, 맨손, 화살, 조총, 창 돌진을 서로 다른 타격 이미지와 소리로 분리한다.
- 공격 예비, 타격 순간, 히트스톱, 피격 광주, 넉백, 잔상 순서가 피해 이벤트와 일치한다.
- 치명타는 크기만 키우지 않고 파열 방향과 짧은 강조 프레임을 추가한다.

### 7속성

- 화염: 불꽃보다 그을음·잔불·연기 중심.
- 빙결: 서리, 균열, 호흡, 발밑 결빙 중심.
- 감전: 짧은 백색 섬광과 금속·습기 전도 중심.
- 중독: 탁한 녹색 얼룩, 호흡 저하, 중첩 표식 중심.
- 바람: 먼지, 천과 풀의 반응, 얇은 칼바람 중심.
- 지맥: 돌 파편, 바닥 균열, 무게감 있는 충격 중심.
- 암영: 검은 연기보다 빛이 줄고 잔상이 어긋나는 표현 중심.

### 상태와 패턴

- 상태 아이콘, 대상 위 월드 효과, 대상 카드 남은 시간은 같은 시각 언어를 사용한다.
- 투사체는 발사자 손·무기에서 시작해 실제 충돌 지점에서 사라진다.
- 보스 장판, 직선, 원뿔, 돌진 경로는 실제 판정과 일치하고 색각 이상에서도 형태로 구분된다.
- 저사양·모바일에서는 파티클 수만 줄이고 핵심 타격 프레임과 판정 가독성은 유지한다.

## 11. HUD·메뉴·지도·스토리 화면 전체 목표

### 공통 인터페이스 언어

- 낡은 목재, 먹선, 황동 장식, 한지 질감을 사용하되 텍스트 주변은 장식을 줄인다.
- 모든 아이콘은 같은 선 굵기와 광원 방향을 사용하고 이모지·임시 문자 아이콘을 남기지 않는다.
- 플레이 화면에는 생존, 현재 대상, 목표, 상호작용, 핵심 스킬만 유지한다.
- 행낭, 인물, 무공, 이야기, 지도, 설정은 각자 고유 목적을 갖고 중복 정보를 줄인다.

### 화면별 목표

- 타이틀: 네 주인공의 분위기는 다르되 동일 세계의 초상·타이포·버튼 체계를 사용한다.
- HUD: 배경과 싸우지 않는 반투명도, 전투 중 읽히는 HP·상태·대상 정보, 모바일 엄지 영역 확보.
- 행낭: 실제 물건을 보는 듯한 아이콘 크기와 비교 정보, 장비 슬롯과 캐릭터 외형의 즉시 동기화.
- 무공: 노드 연결, 잠금 이유, 투자 가능, 장착 상태를 형태와 애니메이션으로 구분.
- 지도: 권역 재질, 도시 랜드마크, 방문·잠금·전쟁 상태, 추천 경로를 겹치지 않게 표시.
- 이야기: 인물 초상, 화자, 선택, 보상, 사건 결과가 한 장면 안에서 읽혀야 한다.
- 설정: 그래픽 품질, 동작 줄이기, 목표 표시, UI 배율의 결과를 즉시 미리보기로 보여준다.

### 반응형 기준

- PC 1536×1024와 1280×720, 모바일 390×844, 가로형 844×390을 기본 검증 크기로 사용한다.
- HUD는 안전 영역을 침범하지 않고 가로 스크롤을 만들지 않는다.
- 메뉴가 열리면 전투 입력을 잠그고 닫은 뒤 포커스와 스크롤을 복원한다.

## 12. 날씨·조명·분위기 목표

- 지역의 시간과 날씨는 단순 전체 색상 필터가 아니라 하늘 밝기, 바닥 습도, 그림자, 안개,
  횃불 반응을 함께 바꾼다.
- 비, 눈, 해풍, 먼지, 연기는 플레이어와 목표를 가리지 않는 밀도 상한을 둔다.
- 실내·동굴·야간은 적과 출구를 잃지 않도록 국소 조명과 실루엣 대비를 유지한다.
- 횃불과 화로의 광원은 객체 위치와 일치하고 화면 밖 효과는 갱신하지 않는다.
- `reducedMotion`에서는 반복 흔들림, 큰 번쩍임, 과도한 파티클을 줄인다.

## 13. 충돌·가림·앵커·애니메이션 기술 목표

- 월드 좌표는 루트 컨테이너, 공격·피격·사망은 자식 스프라이트 로컬 좌표가 담당한다.
- 모든 캐릭터·몬스터는 발 기준점으로 깊이를 계산한다.
- 이미지 유효 영역에서 발판 마스크 초안을 만들고 사람이 최종 검수한다.
- 충돌은 사각형 하나로 모든 객체를 막지 않고 실제 통과 가능한 틈과 출입구를 보존한다.
- 클릭 영역은 보이는 객체보다 과도하게 크지 않으며 가까운 상호작용 규칙을 따른다.
- 애니메이션 키는 `주체-행동-방향-버전` 규칙으로 중앙 등록한다.
- 지역 이동, 사망, 장비 변경, 메뉴 열림 뒤 이전 트윈·대상·이펙트 참조가 남지 않는다.

## 14. 성능과 레거시 정리 목표

- 실제 참조되는 자산 목록을 빌드 시 생성하고 미참조 파일을 배포에서 제거한다.
- 대형 배경은 화면 표시 크기에 맞게 해상도와 WebP 품질을 조정한다.
- 동일한 PNG/WebP 쌍, 사용하지 않는 이전 버전, 생성 미리보기는 `public/`에서 제거한다.
- 아틀라스는 함께 로드되는 작은 객체만 묶고, 한 프레임을 쓰기 위해 거대한 시트를 불러오지 않는다.
- 모바일 DPR은 최대 1.5를 유지하고 화면 밖 객체·파티클·트윈은 휴면 처리한다.
- 장면 최초 진입, 지역 전환, 행낭 최초 열기에서 긴 메인 스레드 정지를 측정한다.
- 목표 예산: 초기 필수 다운로드, 지역 추가 다운로드, GPU 텍스처 메모리, 평균·최저 FPS를
  PC와 모바일 각각 기록하고 이전 배포보다 악화되면 자산을 다시 최적화한다.

## 15. 제작 장부와 자동 검사

다음 장부를 코드에서 생성 가능하게 유지한다.

- `region-visual-matrix`: 81개 지역의 배경, 랜드마크, 객체 세트, 전경, 출구, 날씨.
- `monster-visual-matrix`: 61종의 시트, 공유 등급, 스케일, 발선, 걷기, 공격, 피격, 사망.
- `item-visual-matrix`: 60종의 아이콘, 상세, 드롭, 장착 외형, 획득처.
- `prop-collision-matrix`: 주요 객체의 이미지 영역, 발판, 충돌, 가림, 상호작용 지점, 상태.
- `ui-screen-matrix`: 타이틀, HUD, 행낭, 인물, 무공, 이야기, 지도, 설정의 PC·모바일 상태.

자동 검사는 다음을 포함한다.

- 파일 존재, 중복 키, 미참조 경로, 알파 채널, 투명 모서리, 규격 크기.
- 40프레임 점유, 방향 행, 발선 편차, 프레임 간 크기 변화 8% 이하.
- 모든 카탈로그 ID의 이미지 대응과 런타임 프리로드 등록.
- 이미지 발판과 충돌 영역의 허용 오차, 출구 양방향 연결, 상태 이미지 전환.
- 사용하지 않는 구형 버전이 `public/`에 다시 들어오지 않는 회귀 검사.

## 16. 실제 플레이 검증 행렬

### 대표 지역

- 울릉 감옥→관아→마을→사냥터→해안.
- 영월 지휘소와 전주 전장.
- 한성 성문→저잣거리→궁궐.
- 평양 외곽→대동문→내성.
- 여진 설원부락→변경 전선.
- 세쓰 촌락→오사카 항구→성하마을→성.
- 일반 던전 1개와 보스 층 1개.

### 필수 행동

- 네 주인공 새 게임·이어하기, 빈손 이동·공격, 무기·복장 장착 전환.
- 클릭 이동, 좁은 문 통과, 객체 뒤 가림, NPC 접근, 상점·주막·대장간 상호작용.
- 근접·원거리 몬스터 추적, 공격 예고, 피격, 넉백, 상태이상, 사망·재생성.
- 일반·희귀·영웅 드롭, 바닥 이미지, 자동 접근, 행낭 만석, 상세·비교·장착.
- 성문 잠금·개방, 지역 왕복, 날씨, 야간, 전투 중 메뉴 열기와 닫기.

각 상태는 PC와 390×844 모바일의 전후 스크린샷, DOM 상태 표식, 브라우저 콘솔 로그를 함께
남긴다. 캔버스 화면을 보지 않고 테스트 코드만 통과한 결과는 그래픽 검증으로 인정하지 않는다.

## 17. 전체 완료 판정표

- 81개 지역 시각 장부의 미분류·누락이 0개다.
- 61종 몬스터 외형 대응표의 미분류가 0개이고 모든 보스가 전용 실루엣을 가진다.
- 60종 아이템 모두 아이콘·상세·드롭 표현을 가지며 모든 장착 장비가 월드 외형과 연결된다.
- 고정 실물 객체에 남은 임시 코드 도형이 0개다. 동적 코드 효과는 중앙 프리셋에 등록돼 있다.
- 주요 객체의 이미지·충돌·가림·상호작용·상태 전환 검사가 통과한다.
- 네 주인공의 5방향 걷기·공격과 장비 조합이 실제 상태에 연결된다.
- 모든 몬스터의 걷기·공격이 실제 AI 상태에 연결되고 피해 프레임과 판정이 일치한다.
- PC·모바일 대표 지역 전후 비교에서 HUD 겹침, 가로 넘침, 발선 이탈, 잘못된 깊이 정렬이 없다.
- 구형·중복·미참조 자산이 배포본에 없고 성능 예산이 기록돼 있다.
- `npm test -- --run`과 `npm run build`가 통과한다.
- 실제 브라우저에서 이동·전투·드롭·상호작용·충돌·지역 이동·사망을 검증하고 콘솔 오류가 없다.
- `main` 반영, Firebase Hosting 배포, 최신 해시 자산 응답과 공개 화면을 확인한다.

위 항목 전체가 증거로 확인되기 전에는 ‘그래픽 대개혁 완료’라고 부르지 않는다.

## 18. 실행 의존 순서

숫자로 범위를 축소한 단계가 아니라, 전체 목표를 완성하기 위한 의존 관계다.

1. 장부와 자동 검사를 먼저 만든다.
2. 권역·객체·캐릭터·몬스터·아이템의 기준 이미지와 규격을 승인한다.
3. 배경과 고정 객체를 교체하면서 충돌·가림 데이터를 함께 옮긴다.
4. 캐릭터와 몬스터 시트를 실제 이동·공격 상태에 연결한다.
5. 아이템 아이콘·드롭·장착 외형을 하나의 시각 ID로 통합한다.
6. 전투·속성·상태 효과를 피해 이벤트와 연결한다.
7. HUD·메뉴·지도·스토리 화면을 새 자산 체계와 맞춘다.
8. 레거시 자산과 용량을 정리하고 전체 플레이 검증과 공개 배포를 반복한다.

한 영역을 바꿀 때도 이미지 파일, 데이터 연결, 충돌, 애니메이션, 테스트, 실제 화면 검증을 한 묶음으로
끝낸다. 이미지 파일만 쌓아 두고 나중에 연결하는 방식은 사용하지 않는다.

## 19. 현재 구현 증거와 남은 전체 범위

이 절은 완료 선언이 아니라, 이미 끝난 작업을 다시 만들지 않고 다음 작업을 정확히 이어가기 위한 누적
기록이다. 세부 수치는 `VISUAL_COVERAGE_REPORT.md`와 `MONSTER_ATLAS_AUDIT.md`가 생성한다.

### 현재까지 실제 반영된 것

- 81개 지역, 61종 몬스터, 60종 아이템, 34개 환경 객체 자산을 기계 판독 가능한 장부로 만들었다.
- 평양 성문과 전주 군기·갈대·좌판처럼 고정된 코드 실물을 투명 래스터 아틀라스로 교체했다. 현재
  고정 실물로 판정되는 코드 도형 후보는 0건이며, 남은 130개 도형 호출은 그림자·선택 링·물결·먼지·
  공격 예고처럼 동적 표현인지 계속 분류한다.
- 곰발톱 철갑, 치악산 발톱소도, 염전 의식도, 거제 닻환도, 황주 월철 장창, 평창 표범소도,
  청주 가마환도, 군산 수몰도의 투명 월드 무기 8종을 추가했다. 손 원점과 실제 종류별 표시 배율을
  분리해 건틀릿·소도·환도·장창이 같은 크기로 보이던 문제를 막았다.
- 황주 월철 장창은 필드 장착, 공격, 영웅 바닥 드롭, 습득, 행낭 슬롯, 상세 확대 이미지, 능력치,
  설명과 획득처까지 PC와 390×844 모바일에서 같은 아이템 정체성으로 확인했다. 장착 월드 외형 공백은
  35종에서 27종으로 줄었다.
- 부적·장신구 14종은 기존 승인 아이콘의 물체 정체성을 유지한 256×256 투명 월드 컷아웃으로 전부
  분리했다. 목·손목·허리·등 장착점을 5방향×8동작에 연결하고, 방향 전환 시 등짐만 몸체 앞뒤 깊이를
  바꾸며 작은 착용물은 몸에 완전히 묻히지 않도록 했다. 통영 삼도 신호고의 필드 부착, 무기 동시 전투,
  영웅 바닥 드롭, 습득, 행낭 슬롯·상세 이미지를 PC와 390×844 모바일에서 확인해 장착 외형 공백을
  27종에서 13종으로 줄였다.
- 북방 초원각궁부터 삼척 해풍각궁까지 활 8종은 기존 아이콘의 재질·문양을 참조하되 화살통과 화살을
  제거한 활 단독 원본으로 다시 제작했다. 순녹색 분리, 녹색 번짐 제거, 세로 방향 통일, 256×256 투명
  정규화와 중앙 손잡이 등록을 거쳐 하진의 5방향×8동작 휴대·준비·당김·발사·회수 손 부착표에 연결했다.
  자동 장부의 장착 외형 공백은 13종에서 복장 5종만 남았다. 실제 화면에서는 흰 자작나무 단궁과
  삼족오 뇌궁을 포함해 휴대·당김·발사·회수 프레임을 확대 검수했고, 삼척 해풍각궁 드롭·습득·행낭
  동일성과 장착 장비 우선 선택을 PC·390×844 모바일에서 확인했다.
- 몬스터 활성 시트 38개, 1,520프레임을 실제 알파 픽셀로 전수 검사했다. 정규화 전에는 발선 일치
  638/1,520프레임, 완전 통과 11/38시트였으나 정규화 후 1,520/1,520프레임과 38/38시트가 통과한다.
  빈 프레임은 0개이며, 걷기는 행별 4포즈, 공격은 타격 유지 프레임을 허용해 최소 3포즈를 보장한다.
- 네 공격 칸이 같은 정지 포즈였던 복면 탈영병은 예비 자세, 찌르기, 타격 강조, 회수 자세로 복원했다.
  실제 브라우저에서 접근·공격·플레이어 피격·경직·처치·잔류 시체를 PC와 모바일로 검증했다.
- 선택 캐릭터 회귀 경로에서 `frontier-archer`를 직접 시작해 하진 이름과 하진의 남하연맹록이 뜨고
  김동혁으로 바뀌지 않는 것을 확인했다.
- 공개 자산은 레거시 정리로 460개·315,630,191바이트에서 450개·310,520,274바이트로 줄인 뒤,
  전용 장신구 14개와 전용 활 8개를 추가해 현재 472개·311,601,936바이트다. 고유하지만 퇴역한
  사슬 광부 v2, 멧돼지 PNG, 원주 곰 이전 정규화본은 `assets/legacy/`로 보존했고, 현재 자산과 바이트가
  같은 사슬 광부 v3와 조선 연결부 v1 여섯 개는 제거했다. 동일 내용 중복은 11묶음에서 3묶음으로
  줄었으며, 남은 3묶음은 아이콘과 월드 무기를 의도적으로 함께 쓰는 속성 환도다.

### 아직 완료되지 않아 계속 진행할 것

- 자동 장부에 남은 복장 레이어 5종을 전부 해소하고 하진의 지역별 복장 변화가 5방향·8동작에서
  현재 활·근접 무기와 충돌하지 않도록 검수한다.
- 같은 시트를 공유하는 34종·11그룹을 세력, 병과, 직급, 동물 종 기준으로 분리한다. 규격 통과는
  실루엣 다양성 완료를 뜻하지 않는다.
- 81개 지역 각각에 고유 랜드마크 1개와 생활 흔적 3개 이상이 있는지 별도 지역 장부를 확장하고,
