# 월영록 베타 대개혁 로드맵

그래픽·이미지셋 분야의 전체 완료 기준과 81개 지역·61종 몬스터·60종 아이템의 상세 범위는
[`BETA_GRAPHICS_REFORMATION_MASTERPLAN.md`](BETA_GRAPHICS_REFORMATION_MASTERPLAN.md)를 기준으로 한다.

## 1. 베타의 목표

월영록 베타는 콘텐츠를 더 많이 붙이는 버전이 아니다. 현재 존재하는 주인공 4명, 지역 81곳,
아이템 60종, 몬스터 61종과 각 캠페인이 한 게임처럼 연결되고 안정적으로 플레이되는 상태를
만드는 버전이다.

베타 완료 기준은 다음 다섯 가지다.

1. 선택한 주인공이 외형·이름·스토리·저장 슬롯까지 한 번도 다른 인물로 바뀌지 않는다.
2. 클릭 이동, 충돌 회피, 지역 경계 통과가 막힘·떨림·순간이동 없이 작동한다.
3. 아이템 획득 이유와 드롭 확률, 장비 비교, 다음 목적지가 화면에서 읽힌다.
4. 모든 도시와 사냥터가 월드맵·현장 출구·스토리 목표의 같은 연결 정보를 사용한다.
5. 새 게임부터 주요 캠페인 체크포인트까지 저장/불러오기와 모바일 플레이가 유지된다.

## 2. 작업 원칙

- 베타 안정화가 끝날 때까지 신규 대륙, 신규 주인공, 신규 온라인 모드는 추가하지 않는다.
- 화면에 보이는 것과 실제 판정이 다르면 판정과 데이터를 먼저 고친다.
- 설명 문구로 불편을 덮지 않는다. 목적지, 충돌, 드롭, 상호작용은 화면 표시로 해결한다.
- 한 번 쓰는 장식 이미지보다 반복 사용되는 지형·인물·아이템 세트를 우선 제작한다.
- 지역·드롭·스토리 연결은 문자열을 여러 파일에 복제하지 않고 단일 데이터에서 파생한다.
- PC와 모바일을 별도 제품처럼 검증한다.

## 3. 우선순위

### P0 — 베타를 막는 오류

- 주인공 선택 고정: 김동혁/하진/연화/광해의 선택, 새 게임, 이어하기, 맵 열기·닫기,
  지역 이동, 사망·부활, 저장 복원 전 구간에서 `PlayerOrigin`을 보존한다.
- 시작 중복 입력 차단: 로딩 중 다른 시작 버튼을 다시 누를 수 없게 하고 현재 선택 인물의
  이름·초상·출발지를 로딩 화면에 표시한다.
- 저장 슬롯 검증: 다른 주인공의 저장을 불러오지 않고 손상 저장은 안전한 출발지에서 복구한다.
- 이동 정지 버그: 장애물에 막힌 뒤 걷기 애니메이션만 계속되는 상태, 목적지 미도달 상태,
  경계에서 좌우로 튕기는 상태를 제거한다.
- 충돌 일치: 건물·나무·성문·물가의 보이는 발판/벽과 실제 충돌 영역을 일치시킨다.
- 도시 단절: 월드맵에는 연결됐지만 현장 출구가 없거나 반대 방향 출구가 다른 지역으로 가는
  모든 링크를 양방향 검사한다.
- 스토리 교착: 이벤트 창을 닫은 뒤 입력이 영구 잠기거나, 목표 완료 후 다음 사건이 열리지 않는
  상태를 제거한다.

### P1 — 플레이 편의성과 화면 가독성

- 현재 목표 고정 표시: 화면 우측 상단에 `주 목표 1개 + 선택 목표 1개 + 거리/방향`만 표시한다.
- 상호작용 표시: NPC, 문, 배, 사다리, 드롭 아이템에 접근 거리와 사용 키/터치 표시를 붙인다.
- 이동 피드백: 클릭 지점, 계산된 도착점, 막힌 지점을 서로 다른 표식으로 보여준다.
- 도시 출구 표지: 출구 앞에 목적지, 위험도, 권장 품계, 이동 조건을 표시한다.
- 월드맵 상태: 현재 위치, 방문 여부, 잠금 이유, 스토리 목적지, 빠른 이동 가능 여부를 구분한다.
- HUD 정리: 전투 중에는 체력·대상·기술·목표만 남기고 인벤토리/스토리/세력 정보는 창으로 분리한다.
- 모바일 조작: 공격·회피·기술 버튼 간격을 확보하고 화면 가장자리와 시스템 제스처 영역을 피한다.
- 피드 알림 우선순위: 레벨업, 희귀 드롭, 목표 완료는 유지하고 반복 피해·일반 획득 문구는 묶는다.
- 설정 보강: UI 크기, 카메라 흔들림, 피해 숫자, 자동 줍기, 목표 추적을 켜고 끌 수 있게 한다.

### P1 — 움직임과 충돌

- 클릭 목적지가 장애물 내부면 가장 가까운 안전 지점으로 투영한다.
- 직선 이동이 막히면 짧은 우회 경로를 찾고, 실패하면 즉시 멈추며 막힘 표식을 표시한다.
- 지역 경계 전후 1초 동안 같은 경계를 다시 밟아 왕복하는 현상을 막는다.
- 플레이어, 추종자, 몬스터의 충돌 반경과 발 그림자 크기를 같은 기준으로 맞춘다.
- 원거리 몬스터가 벽 너머에서 공격하지 않도록 시야선 검사를 적용한다.
- 추종자가 좁은 문에서 플레이어를 밀거나 길을 막지 않도록 통과 우선권을 플레이어에게 준다.
- 공격·피격·회피 중 월드 좌표와 로컬 액션 좌표를 분리해 미끄러짐과 순간 복귀를 제거한다.

### P1 — 아이템과 드롭 경제

- 모든 몬스터에 `주요 드롭`, `희귀 드롭`, `보장 드롭`, `드롭 없음`을 명시한 테이블을 둔다.
- 일반 몬스터는 체감 가능한 재료 드롭을 제공하고, 강력한 장비는 정예·보스·사건 보상으로 분리한다.
- 첫 핵심 아이템은 보장하고 이후에는 누적 실패 보정(천장)을 적용한다.
- 같은 희귀 장비를 이미 보유했을 때는 재료나 강화 자원으로 대체한다.
- 드롭 바닥 표시에 희귀도 색, 이름, 자동 소멸 시간, 가방 부족 상태를 보여준다.
- 선택형 자동 줍기: 재료/일반/희귀 등급별로 설정하고 가방이 가득 차면 이유를 표시한다.
- 아이템 비교: 장착 중인 장비 대비 증가/감소 수치를 색과 화살표로 표시한다.
- 획득 경로: 아이템 상세에 어느 지역의 어떤 적/사건에서 나오는지 기록한다.
- 드롭률 숫자는 개발자용 검증 화면과 테스트에서 확인하고, 플레이 화면에는 희귀도와 획득처를 중심으로 표시한다.

### P1 — 맵과 도시 연결

- `RegionConnection`을 단일 원본으로 만들고 월드맵 선, 현장 출구, 목적지 문구, 이동 조건이 이를 공유한다.
- 모든 연결은 `A → B`와 `B → A`를 검사하고 일방통행은 이유를 데이터에 명시한다.
- 도시는 최소한 입구, 장터/서비스, 스토리 인물, 다음 지역 출구의 네 구역이 화면에서 구분돼야 한다.
- 연결로에는 바닥 길, 표지판, 미니맵 선, 화면 가장자리 목적지 표시를 함께 둔다.
- 바다 이동은 배/항구를 통해서만 일어나며 출항 조건과 도착 항구를 확인창에 보여준다.
- 방문한 도시는 빠른 이동 후보가 되지만 전투·스토리 봉쇄 중에는 잠금 이유를 표시한다.
- 81개 지역 전체를 다르게 꾸미기보다 동일 권역의 지형 세트를 공유하고 랜드마크로 정체성을 만든다.

### P1 — 스토리와 이벤트

- 각 장은 `도입 → 플레이 목표 → 변화 → 보상/다음 목적지` 네 단계가 실제 게임 상태와 연결돼야 한다.
- 이벤트 발생 조건, 완료 조건, 재생 여부, 저장 체크포인트를 한 데이터 구조에서 관리한다.
- 이미 본 긴 장면은 요약 후 건너뛸 수 있고, 중요한 선택지는 다시 확인한다.
- 목표가 바뀌면 HUD, 월드맵, 현장 표지, 이야기 기록이 동시에 갱신된다.
- 전투 중 이벤트 팝업이 열리지 않게 하고 안전 시점까지 대기열에 둔다.
- 주인공별 말투·세력·출발지와 무관한 김동혁 전용 문구를 전수 검사한다.
- 역사적 배경과 가상 설정을 기록 화면에서 구분한다.
- 주요 선택의 결과는 즉시 숫자만 바꾸지 않고 다음 NPC 배치, 도시 상태, 지원 병력에 반영한다.

### P1 — 이미지셋 대개혁

#### 공통 미술 방향

- 명칭: 조선 다크 판타지 베타 비주얼 시스템.
- 핵심 정서: 전란, 비, 안개, 젖은 나무와 돌, 희미한 등불 속에서 살아남는 사람들.
- 색: 먹색·남색·젖은 갈색 70%, 지역 고유색 20%, 불빛·무기·눈빛 강조 10%.
- 비율: 성인 6~7등신. SD, 과장된 갑옷, 현대 판타지 장식은 금지한다.
- 조명: 화면마다 광원 방향을 하나로 고정하고 캐릭터·건물·소품 그림자를 맞춘다.
- 원근: 플레이 영역은 발 위치가 읽히는 3/4 시점, 원경은 수평선과 안개로 분리한다.
- 실루엣: 실제 표시 크기 약 90~100px에서도 직업, 무기, 적/아군이 구분돼야 한다.

#### 반드시 먼저 만들 이미지 세트

1. 권역별 지형 베이스 6종: 울릉, 조선 내륙, 한성/궁궐, 북방, 일본, 해안/항구.
2. 연결로 세트: 흙길, 돌길, 성문 통로, 다리, 선착장, 산길 가장자리와 전환 스트립.
3. 충돌 기준 소품: 나무, 바위, 담장, 집, 성문, 우물, 장터 좌판을 바닥 접점이 보이게 제작한다.
4. 도시 랜드마크: 각 도시 1개 핵심 건물과 표지판. 배경 전체보다 출구와 서비스 위치가 먼저 읽혀야 한다.
5. 몬스터 계열 시트: 인간형 병사, 짐승, 원귀, 도깨비를 계열별로 통일하고 색만 바꾼 복제를 줄인다.
6. 아이템 아이콘 세트: 무기/복장/부적/재료/문서의 외곽 프레임과 광원 방향을 통일한다.
7. UI 세트: HUD 프레임, 버튼 상태, 목표 표식, 출구 화살표, 희귀도 광, 상태이상 아이콘.
8. 스토리 세트: 주인공 초상, 주요 NPC 반신상, 장면 배경. 대사는 이미지에 직접 넣지 않는다.

#### 제작 규격

- 캐릭터·몬스터는 `docs/SPRITE_MODELING_GUIDE.md`의 256px 셀, 8열 × 5행, 발 기준선을 따른다.
- 생성 원본은 런타임에 바로 넣지 않고 투명화, 프레임 분리, 발선 정규화, 축소 미리보기를 거친다.
- 환경 소품은 투명 PNG/WebP 768px 이내, 단일 객체, 명확한 바닥 접점을 사용한다.
- 아이템 아이콘은 256 × 256px, 중앙 70~82% 영역에 물체를 배치하고 글자·배경 풍경을 넣지 않는다.
- UI 장식은 정보를 가리지 않는 낮은 대비로 만들고 버튼의 기본/호버/누름/비활성 상태를 모두 제공한다.
- 기존 이미지의 단순 교체가 아니라 충돌 발판, 상호작용 위치, 애니메이션 상태와 함께 검증한다.

#### 현재 자산·화면 조사 결과

현재 파일 수만 보면 환경 207개, 아이템 77개, UI 43개, 캐릭터 57개지만 몬스터는 36개,
전투/상태 효과는 3개뿐이다. 몬스터 데이터 61종과 비교하면 전용 외형의 공백과 재사용 비율이
크고, 아이템은 수량 추가보다 계열·광원·테두리·실루엣의 통일이 먼저다.

파일을 계열별로 대조하면 추가 제작 전에 정리할 자산도 많다.

- 환경에는 갈대, 깃발 4프레임, 등롱, 물결, 배, 수레, 마을 건물 아틀라스가 이미 있다.
  같은 대상을 런타임 코드 도형으로 다시 그린 부분은 신규 생성을 하지 말고 기존 자산을 먼저 연결한다.
- 기존 소품은 세부 묘사가 훌륭하지만 512/768/1254/1536px 단위와 원근이 혼재한다. 게임 내
  기준 사람 높이, 문 폭, 바퀴 크기, 그림자 농도로 정규화하지 않으면 고급 그림도 붙여 놓은 듯 보인다.
- `v1~v4`, 원본 PNG와 런타임 WebP, 정규화 전/후 파일이 같은 폴더에 섞여 있다. 자산 목록에
  `source`, `runtime`, `superseded`, `region`, `scale`, `anchor`, `collisionPreset`을 기록한다.
- 캐릭터 57개 중 상당수가 김동혁의 몸/갑옷/무기 레이어 변형이다. 다른 주인공, 민간인,
  서비스 NPC의 월드 시트와 초상 대응 비율을 우선 보충한다.
- 현재 행낭 배경은 사방의 금속 장식이 강하고 내부 대비가 낮아 작은 글씨와 슬롯을 압박한다.
  다음 UI 세트는 얇은 9-slice 모서리, 독립 제목띠, 내용 배경으로 모듈화한다.

실제 브라우저 플레이 화면에서는 다음 문제가 확인됐다.

- 메인 HUD는 좌상단 인물 정보, 우상단 목표/미니맵, 좌하단 전투 기록, 하단 기술줄과 메뉴가
  동시에 경쟁한다. 글자는 작은데 장식 프레임이 차지하는 면적은 크다.
- 행낭은 장비·가방·세부 능력치·사냥 기록·아이템 상세를 한 화면에 넣어 정보 위계가 흐리다.
  빈 슬롯이 화면 대부분을 차지하고, 작은 글씨로 된 하단 능력치는 화면 크기에 따라 잘릴 수 있다.
- 무공 화면은 습득처와 등급이 적힌 카드 목록이며, 선행 기술·분기선·갈림길·빌드 정체성이
  보이는 실제 스킬트리는 아니다.
- 일부 성문, 장터 차양, 깃발, 갈대, 수레와 표지물은 코드 도형과 서로 다른 화풍의 이미지가
  섞여 있어 조명·원근·크기·바닥 접점이 어색하다.
- 전투 중 기본 대상이나 이전 대상이 남아 있는지 구분하기 어려워, 사거리 밖/사망/지역 이동 시
  대상 패널을 즉시 비우는 회귀 검사가 필요하다.

#### 객체 이미지셋 전수 정비표

환경 객체는 단순히 예쁜 그림을 추가하지 않고 `외형 이미지 + 발판 마스크 + 상호작용 지점 +
미니맵 표식 + 파괴/사용 상태`를 한 묶음으로 관리한다.

1. **길과 경계**: 직선/곡선/삼거리 흙길, 돌길, 눈길, 진흙길, 해안길, 절벽 가장자리,
   여울, 징검다리, 목교, 석교, 성문 통로, 선착장과 각 지형 사이 전환 타일.
2. **울릉·해안**: 젖은 현무암, 해초, 갈대, 파손 어망, 밧줄 더미, 닻, 작은 배, 부두 기둥,
   생선 좌판, 물통, 해안 제단, 봉수대, 풍랑 잔해.
3. **조선 마을·도시**: 초가/기와집 변형, 대문, 담장 모서리, 우물, 장독대, 빨랫줄,
   곡식 가마, 짚단, 손수레, 말뚝, 등롱, 약방/대장간/주막/관아 표지, 장터 차양과 좌판.
4. **궁궐·군영**: 홍살문, 궁문, 행랑, 회랑 기둥, 병풍, 횃대, 북, 무기 거치대, 군량 상자,
   지휘 깃발, 목책, 방책, 감시탑과 파손 상태.
5. **산림·북방**: 소나무/활엽수 계절 변형, 그루터기, 바위 군집, 눈더미, 얼음 가장자리,
   사냥 덫, 야영 천막, 모닥불, 말 먹이통, 토템, 버려진 수레.
6. **일본 권역**: 지역 건축 비례를 살린 문/담장/상점/신사 소품을 별도 세트로 만들되,
   조선 객체의 단순 색상 변경으로 처리하지 않는다.
7. **폐허·괴이 지역**: 불탄 들보, 무너진 벽, 봉인 줄, 부적 기둥, 묘비, 제물상, 뼈더미,
   오염 웅덩이, 원혼등, 균열과 정화 전/후 상태.
8. **서비스 식별물**: 상점, 수리, 창고, 숙박, 선박, 훈련, 이야기 인물은 건물 외형과
   작은 심볼을 함께 제공하고 화면 밖에서도 방향 표식으로 찾을 수 있게 한다.
9. **상호작용 상태**: 문 열림/닫힘, 상자 닫힘/열림, 횃불 꺼짐/점화, 제단 비활성/활성,
   다리 정상/붕괴, 좌판 영업/폐점처럼 플레이 결과가 이미지에 남게 한다.
10. **배경 생동감**: 깃발 천, 빨래, 불꽃, 연기, 물결, 얕은 풀은 짧은 루프 애니메이션을
    제공하되 충돌 객체 전체를 흔드는 방식은 금지한다.

다음 요소는 코드 렌더링을 유지한다: 선택 원, 충돌 디버그, 범위 예고, 그림자, 빛 번짐,
빗방울, 눈발, 물결 파동, 이동 먼지와 짧은 파티클. 반대로 성문·문짝·깃발 천·좌판·차양·갈대·
수레·가구·부두 시설·표지판은 실제 이미지셋으로 교체한다.

#### 인물·몬스터 이미지셋

- 61종 몬스터를 `전용 시트 있음 / 계열 공유 허용 / 색상 변형 허용 / 보스 전용 필수`로
  표로 관리하고, 데이터만 다르고 외형이 같은 적을 플레이어에게 다른 종처럼 소개하지 않는다.
- 일반 인간형은 체형 3종, 무기 자세, 투구/복식 레이어로 변주한다. 보스와 이야기 핵심 적은
  독립 실루엣, 피격, 공격 예고, 사망 연출을 갖는다.
- 짐승은 두 발 인간형 리깅을 억지로 쓰지 않고 종별 보행 구조를 적용한다.
- 원귀·도깨비는 투명도만 바꾼 인간으로 만들지 않고 관절, 중심 높이, 이동 흔적을 달리한다.
- 민간인과 서비스 NPC는 연령·직업·계층·지역이 읽히는 기본 12종을 먼저 만들고, 대화 인물은
  초상과 월드 스프라이트의 머리 장식·색·무기를 일치시킨다.
- 네 주인공은 대기·보행·공격·피격·회피·사망의 방향 일관성을 확인하고, 장착 무기가 손에서
  분리되거나 발선이 흔들리는 프레임을 전수 교정한다.

#### 아이템·행낭용 이미지셋

- 아이콘 계열을 도검, 창/둔기, 활/화기, 갑주, 의복, 장신구, 부적, 약품, 음식, 재료,
  사건 물품, 문서/지도, 화폐로 재분류한다.
- 같은 계열은 화면 축소 상태에서도 칼날 방향, 병 모양, 두루마리 묶음처럼 형태로 구분하고,
  희귀도는 물건 자체의 과한 발광이 아니라 슬롯 테두리와 작은 광택으로 표현한다.
- 장착 장비는 `256px 아이콘 + 512px 상세 그림`을 제공한다. 행낭 우측 상세에서 작은 아이콘을
  억지로 확대하지 않는다.
- 바닥 드롭은 아이콘과 별개의 간결한 픽업 이미지, 그림자, 희귀도 기둥, 이름표를 사용한다.
- 사건 물품은 일반 잡동사니와 다른 봉인/문양 체계를 사용하고 버리기·판매를 기본 금지한다.
- 빈 슬롯, 잠긴 슬롯, 신규 획득, 장착 중, 즐겨찾기, 비교 대상, 퀘스트용 상태 이미지를 통일한다.
- 장비 외형 반영은 베타에서 무기와 핵심 투구만 우선 적용하고, 모든 복장을 종이인형처럼
  겹치는 시스템은 애니메이션 품질이 확보될 때까지 미룬다.

#### 전투·상태 효과 이미지셋

현재 효과 자산 3개는 전투 판독에 부족하므로 다음 아틀라스를 우선한다.

- 물리: 베기 3방향, 찌르기, 둔기 충격, 방패 방어, 튕김, 치명타, 갑옷 파손.
- 투사체: 화살, 화살 궤적, 총탄/화약 연기, 투척물, 벽 충돌과 대상 적중.
- 속성: 화염, 냉기, 번개, 독, 출혈, 신성/정화, 원혼/저주의 작은·중간·강한 단계.
- 상태: 기절, 속박, 둔화, 공포, 침묵, 방어 상승/하락, 지속 회복, 표식과 해제.
- 이동: 흙먼지, 진흙, 얕은 물, 눈, 풀밭 발자국. 지면 재질과 맞지 않는 먼지는 띄우지 않는다.
- 사건: 조사 가능, 봉인, 위험 경고, 선택 결과, 목표 완료를 전투 효과와 다른 형태로 구분한다.

#### 이미지 제작 수락 기준

- 실제 게임 크기 100%, 75%, 모바일 축소 화면에서 실루엣과 상호작용 지점이 읽힌다.
- 광원은 좌상단 기준을 기본으로 하고 지역 특수 광원이 있으면 세트 전체를 함께 바꾼다.
- 모든 월드 객체는 발판 마스크가 이미지 밖으로 튀지 않고, 문과 다리는 통과 가능 폭을 표시한다.
- 투명 가장자리의 흰 테두리, 배경 잔여물, 프레임 점프, 무기 잘림을 자동 검사한다.
- 신규 시트는 보행·공격 상태에 실제 연결하고, 정지 이미지를 흔들어 움직임을 흉내 내지 않는다.
- 원본, 정리본, 런타임 WebP/PNG, 미리보기, 출처/프롬프트를 분리 보관한다.

### P1 — 능력치와 성장 구조 개혁

#### 기본 능력치

베타는 레벨 숫자만 오르는 성장이 아니라 주인공의 역할이 실제 조작과 선택에 드러나야 한다.

- `근력`: 근접 피해, 경직, 무거운 장비 효율.
- `기교`: 명중, 치명타, 원거리 피해, 약점 공격.
- `체력`: 최대 생명력, 방어, 경직 저항.
- `신법`: 회피 성능, 이동 기술, 행동 회복. 이동 속도는 과도하게 누적되지 않도록 상한을 둔다.
- `정신`: 주술 피해, 상태이상 적중/저항, 기술 자원.
- `통솔`: 추종자 생존력, 지원 기술, 세력·도시 사건의 일부 선택지.

레벨마다 모든 수치를 직접 배분하게 만들지 않는다. 주인공별 자동 성장에 더해 2레벨마다
`수련점 1점`을 주고, 플레이어가 선택한 두 능력치를 보강한다. 안전 지역에서는 베타 기간 동안
저렴하게 초기화할 수 있게 해 빌드 실험을 막지 않는다.

#### 파생 능력치와 화면 표시

- 공격력, 방어력, 최대 생명력, 명중, 회피, 치명타 확률/피해, 경직 저항, 상태 저항,
  기술 재사용, 이동 보정, 추종자 보정으로 정리한다.
- 능력치에 마우스를 올리거나 터치하면 `기본 + 능력치 + 장비 + 버프` 계산 근거를 보여준다.
- 실제 적용되지 않는 장식용 숫자는 삭제한다. 전투력은 참고값으로 표시하고 세부 수치보다
  우선하지 않는다.
- 장비 교체 전후 변화, 다음 레벨 예상치, 현재 걸린 상한을 같은 자리에서 확인한다.
- 피해 공식은 테스트 가능한 하나의 모듈로 옮기고 HUD, 행낭, 전투가 같은 값을 사용한다.

#### 주인공별 성장 정체성

- 김동혁: 근력·체력 기반의 전열, 반격과 경직 제어.
- 하진: 기교·신법 기반의 거리 유지, 약점과 연속 사격.
- 연화: 정신·신법 기반의 봉인, 상태 제어와 정화.
- 광해: 통솔·체력 기반의 지휘, 호위와 전장 통제.

어느 주인공이든 기본 탐험과 보스 처치가 가능해야 하며, 특정 능력치가 낮다는 이유로 주 캠페인이
막히면 안 된다. 능력치 선택은 해법과 리듬을 바꾸되 진행 권한을 박탈하지 않는다.

### P1 — 진짜 스킬트리 개혁

현재 카드 목록을 다음 네 갈래가 연결된 노드형 수련도로 교체한다.

1. `기본 무예`: 기본 공격 연계, 방어/회피, 자원 회복.
2. `주인공 전용`: 김동혁 반격, 하진 사격, 연화 봉인, 광해 지휘처럼 고유 플레이를 강화한다.
3. `생존·기동`: 이동기, 해제, 회복, 위험 회피. 공격력만 올리는 수동 노드는 줄인다.
4. `비전`: 스승, 비급, 사건으로 열린 기술. 획득 전에도 실루엣과 개방 조건을 보여준다.

각 노드는 1~3등급이며 다음 등급의 수치와 동작 변화를 미리 보여준다. 단순 `피해 +5%`보다
공격 범위 변화, 추가 타격, 상태 연계, 회피 후 반격처럼 조작이 달라지는 등급을 우선한다.

- 분기선, 선행 조건, 필요 수련점, 습득처, 현재 장착 여부를 한 화면에 표시한다.
- 한 갈래를 선택하면 다른 갈래를 영구 폐쇄하지 않는다. 핵심 선택만 상호 배타로 만들고
  안전 지역에서 초기화할 수 있게 한다.
- 액티브 기술은 제한된 단축 슬롯에 장착하고, 패시브는 별도 장착 한도를 둬 선택 의미를 만든다.
- 비급을 먹었는데 배울 수 없는 경우 필요한 선행 노드와 스승 위치를 즉시 안내한다.
- 키보드, 패드, 터치에서 노드 탐색과 확대/이동이 가능해야 하며 색만으로 잠금 상태를 구분하지 않는다.
- 각 주인공별 최소 3개 실전 빌드를 테스트한다: 안정형, 공격형, 고유 기믹형.

### P1 — 인터페이스 대개혁

현재 3,214줄인 단일 HUD 구현에서 행낭, 수련도, 이야기 기록, 월드맵을 각각의 화면 제어기와
표시 컴포넌트로 분리한다. 게임 상태와 DOM 표시를 분리해 한 창을 고쳤을 때 다른 창이 깨지는
회귀를 줄인다.

#### 메인 HUD

- 평상시: 생명력/자원, 현재 목표, 미니맵, 상호작용만 표시한다.
- 전투 진입: 대상 정보, 기술 단축줄, 상태이상과 중요한 전투 기록을 확장한다.
- 메뉴를 열면 전투 입력을 확실히 잠그고 닫을 때 이전 입력 상태를 복구한다.
- 화면 모서리 네 곳에 정보를 쌓는 구조를 줄이고, 하단 메뉴는 아이콘 수와 높이를 축소한다.
- 대상이 죽거나 사거리에서 벗어나거나 지역을 바꾸면 대상 패널과 자동 공격을 함께 해제한다.

#### 행낭과 장비

- 데스크톱은 `장비/인물 요약 | 5×4 가방 | 상세/비교`의 세 영역으로 정리한다.
- 사냥 기록은 행낭에서 빼고 도감으로 이동한다. 세부 능력치는 인물 창의 별도 탭으로 옮긴다.
- 빈 가방에서는 패널 높이를 억지로 채우지 않고 정렬, 필터, 자동 줍기 설정을 먼저 안내한다.
- 클릭 장착, 더블클릭 사용, 드래그 장착을 모두 지원하되 같은 결과를 내고 취소/복구가 가능해야 한다.
- `최근 획득`, `장착 가능`, `더 강함`, `퀘스트`, `즐겨찾기`, `판매 제외` 필터를 제공한다.
- 버리기·판매·분해는 희귀도와 즐겨찾기를 검사하고, 여러 개 처리할 때 최종 결과를 확인시킨다.
- 모바일은 장비/가방/상세를 탭으로 분리하고 최소 44px 터치 영역과 하단 안전 여백을 보장한다.

#### 인물/능력치 창

- `개요`, `능력치`, `장비`, `효과`, `평판` 탭으로 분리한다.
- 개요에는 역할, 전투력, 주 능력치, 현재 빌드, 다음 성장 목표만 보여준다.
- 능력치 탭에는 계산 근거, 상한, 장비 교체 예상치와 전투 도움말을 제공한다.
- 상태이상·버프는 아이콘, 남은 시간, 발생 원인, 해제법을 함께 보여준다.

#### 스킬·이야기·지도·도감

- 수련도는 화면을 충분히 쓰는 노드 그래프로 만들고 현재 단축 슬롯과 비교 미리보기를 고정한다.
- 이야기 기록은 `주 이야기`, `의뢰`, `완료`, `인물/세계관`으로 나누고 현재 장의 목표를 먼저 연다.
- 월드맵은 지역 목록보다 연결선과 이동 조건을 중심으로 구성하고 현재 경로를 단계별로 보여준다.
- 도감은 몬스터, 아이템, 지역을 분리하고 미발견 정보는 추측 가능한 범위만 공개한다.
- 상점, 제작, 대화, 선택창은 제목/닫기/비용/결과/확인 위치를 같은 규칙으로 통일한다.

#### UI 시각·접근성 규칙

- 먹색 바탕, 낡은 종이, 무광 청동을 쓰되 모든 패널에 두꺼운 장식 테두리를 반복하지 않는다.
- 본문은 데스크톱 14px, 모바일 13px를 기본으로 하고 중요 수치는 최소 15px 이상으로 둔다.
- 기본/호버/포커스/누름/선택/비활성 상태를 모두 만들고 키보드 포커스를 숨기지 않는다.
- 희귀도, 적아군, 잠금 상태는 색 + 아이콘 + 문구로 동시에 구분한다.
- UI 배율 80~130%, 고대비 목표, 자막 속도, 화면 흔들림, 번쩍임, 피해 숫자, 자동 줍기,
  홀드/토글 입력을 설정에서 조절한다.
- 설명은 긴 문단 대신 핵심 효과, 조건, 수치, 획득처 순으로 표시하고 자세한 세계관은 별도 기록으로 뺀다.

### P1 — 편의성과 RPG 생활 품질

- 최근 방문 도시와 현재 임무까지의 추천 경로를 제공하되 미방문 지역을 자동 해금하지 않는다.
- 상인에게 전체 판매 대신 `잡동사니만`, 잠금/즐겨찾기 제외, 판매 결과 미리보기를 제공한다.
- 창고는 도시 간 공유하고 사건 물품은 별도 무게 없는 보관함에 둔다.
- 사망 시 잃는 것, 부활 위치, 내구/비용을 사망 전에 알 수 있게 하고 억울한 진행 손실을 막는다.
- 전투 밖에서는 장시간 누르지 않아도 체력/자원이 회복되는 안전 규칙을 명확히 한다.
- NPC 머리 위 표식은 새 대화, 진행 중, 완료 가능, 서비스, 반복 의뢰를 구분한다.
- 장비와 스킬 프리셋은 주인공당 3개를 제공하되 전투 중 교체는 금지한다.
- 튜토리얼은 첫 상황에서 한 기능씩 보여주고 설정에서 다시 볼 수 있게 한다.
- 조작 키 변경, 패드 버튼 표기 자동 전환, 터치 버튼 위치/크기 조정을 제공한다.
- 저장 슬롯에 주인공 초상, 현재 지역, 플레이 시간, 장, 저장 버전과 손상 여부를 표시한다.

### P1 — 버그 전수 조사 장부

모든 버그는 `재현 절차 / 기대 결과 / 실제 결과 / 주인공 / 지역 / 입력 장치 / 저장 버전 /
스크린샷 / 수정 커밋 / 회귀 테스트`를 갖는다.

- 주인공 일관성: 선택, 로딩, 대사, 초상, 능력, 저장, 부활, 빠른 이동.
- 입력: 메뉴 중 공격, 중복 클릭, 키 고정, 모바일 멀티터치, 패드 전환.
- 이동: 장애물 고착, 좁은 문, 경계 왕복, 추종자 밀기, 클릭 위치 오차.
- 전투: 벽 너머 공격, 사망 대상 유지, 무적 시간, 연속 피격, 드롭 중복.
- UI: 잘림, 겹침, 스크롤 분실, 창 중첩, 닫기 후 잠금, 작은 해상도.
- 데이터: 잘못된 획득처, 드롭 합계, 빈 문자열, 없는 지역 연결, 번역되지 않은 인물명.
- 스토리: 순서 역전, 재접속 중복, 건너뛰기 후 보상 누락, 선택 결과 미반영.
- 저장: 버전 이전, 부분 손상, 전투 중 저장, 지역 이동 중 저장, 다른 주인공 혼입.
- 성능: 첫 진입 끊김, 이미지 해제 누락, 장시간 플레이 메모리, 저사양 모바일 발열.

### P2 — 추가해도 되는 제한적 기능

- 자동 줍기 필터와 목표 추적.
- 방문 도시 빠른 이동.
- 드롭 획득처 도감.
- 이벤트 다시보기와 건너뛰기.
- 막힌 이동 지점 표시와 출구 길안내.
- 접근성 설정: UI 배율, 흔들림 감소, 피해 숫자, 고대비 목표 표시.

### 베타 이후로 미룰 기능

- 신규 주인공과 신규 국가.
- 새로운 대규모 대륙/지역 묶음.
- 길드, 경매장 확장, 대규모 PvP.
- 장비 슬롯 추가와 복잡한 제작 트리.
- 캐릭터 전직과 신규 스킬 계통.
- 현재 캠페인과 연결되지 않는 독립 던전.

## 4. 실행 순서

### 0차 — 기준선과 조사 장부

네 주인공별 새 게임 저장을 만들고, PC/모바일 기준 화면을 캡처한다. 61종 몬스터, 60종 아이템,
81개 지역, 모든 출구와 주요 객체의 현재 이미지·판정·데이터 연결 상태를 표로 고정한다.

### 1차 — 베타 차단 버그

주인공 선택/저장, 입력 잠금, 이동 정지, 충돌, 지역 왕복, 스토리 교착을 수정한다.

### 2차 — UI 기반 분리와 메인 HUD

단일 HUD에서 행낭, 인물, 수련도, 이야기, 지도, 도감을 분리하고 메뉴 입력 잠금과 반응형 레이아웃을
먼저 안정화한다. 이후 화면 개혁은 이 기반 위에서 진행한다.

### 3차 — 이동과 도시 연결

단일 지역 연결 데이터, 양방향 검사, 현장 출구, 미니맵/월드맵 길안내를 맞춘다.

### 4차 — 움직임·충돌과 객체 이미지

발판 마스크와 충돌을 맞추고 코드 도형인 성문·좌판·깃발·갈대·수레·표지물을 이미지셋으로 교체한다.
클릭 이동, 좁은 문, 추종자, 지역 경계와 상호작용 표식을 함께 검증한다.

### 5차 — 행낭·아이템과 드롭

행낭 정보 위계를 고친 뒤 아이콘/상세/바닥 드롭 이미지, 드롭 테이블·천장·중복 보상·자동 줍기·
장비 비교·획득처를 완성한다.

### 6차 — 능력치와 스킬트리

하나의 능력치 계산 모듈, 인물 창, 수련점, 네 갈래 노드 그래프, 초기화, 단축 슬롯과 세 가지
대표 빌드를 구현하고 전투 난이도를 다시 조정한다.

### 7차 — 몬스터·전투 이미지셋

61종 외형 대응표의 공백을 채우고 보스 전용 시트, 공격 예고, 피격/사망, 물리·투사체·속성·상태
효과 아틀라스를 연결한다.

### 8차 — 권역·도시·스토리 이미지와 사건 연결

권역 베이스, 도시 랜드마크, NPC 초상, 사건 장면을 정비하고 네 주인공의 목표/이벤트/체크포인트/
도시 상태를 실제 플레이 결과와 연결한다.

### 9차 — 편의성·접근성 마감

목표 추적, 자동 줍기, 필터, 프리셋, 키 변경, UI 배율, 고대비, 진동/흔들림/번쩍임 설정과
패드·터치 조작을 완성한다.

### 10차 — 베타 검증

전체 자동 테스트와 빌드 후 네 주인공 각각 새 게임, 이어하기, 맵 왕복, 도시 이동,
사망·부활, 희귀 드롭, 주요 사건을 PC와 모바일에서 플레이한다.

### 권장 배포 단위

- `Beta 0.1 안정화`: 주인공/저장/이동/충돌/스토리 교착.
- `Beta 0.2 인터페이스`: HUD 분리, 행낭, 인물 창, 지도, 모바일 레이아웃.
- `Beta 0.3 성장`: 능력치, 수련점, 노드형 스킬트리, 전투 재조정.
- `Beta 0.4 월드 아트`: 객체, 권역, 몬스터, 효과 이미지셋과 도시 연결.
- `Beta 0.5 콘텐츠 연결`: 아이템 경제, 스토리 사건, 도시 변화, 도감.
- `Beta RC`: 네 주인공 전체 회귀, 성능, 접근성, 배포 캐시 검증.

각 단위는 메인에 합치기 전에 자체 테스트와 실제 플레이를 통과한다. 이미지 원본만 들어오고
게임 상태·충돌·애니메이션에 연결되지 않은 작업은 완료로 계산하지 않는다.

- `Beta 0.4 일부`: 물리 타격 이미지 아틀라스를 베기·찌르기·둔격·치명타 이벤트에 연결하고,
  지역 이동·사망 뒤 남는 대상 참조를 시뮬레이션에서 즉시 정리한다.
- `Beta 0.2`: 모바일에서는 사용할 수 없는 원군 호출부를 접어 동행 부대가 플레이 화면을 덮지 않게 했다.
- `Beta 0.4 일부`: 화상·빙결·감전·중독·칼바람·지맥·암영 아이콘을 실제 대상 상태와 남은 시간,
  독 중첩에 연결하고 모바일에서는 아이콘과 시간만 남긴다.
- `Beta 0.5 일부`: 모든 몬스터에 속성 약점 `+30%`와 저항 `-35%`를 실제 상태 지속·피해에 연결하고,
  대상 카드에서 주요·희귀 전리품, 첫 확정 보상과 8회 토벌 보정 진행도를 확인할 수 있게 했다.
- `Beta 0.2`: NPC 원격 클릭을 즉시 대화·상점 열기로 처리하지 않고, 클릭·`F`·터치 공용 근접
  상호작용 프롬프트와 자동 접근으로 통합했다. 상호작용 시작 시 이동·전투·자동 줍기 대상도 안전하게 해제한다.
- `Beta 0.2`: 일시정지 메뉴에 즉시 수동 저장을 추가하고, 현재 목표 HUD를 설정에서 숨기거나 다시
  표시할 수 있게 했다. PC와 390×844 모바일에서 상호작용 프롬프트의 겹침과 가로 넘침을 검증했다.
